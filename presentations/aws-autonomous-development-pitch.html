The 5-Step Autonomous Workflow

From detection to deployment, fully automated with AWS

1

Automated Issue Detection

Trigger: GitHub Actions (scheduled) OR manual run

Script: run-diff-checker.py scans 30 services

Detects: Code standards violations, missing tests, compliance gaps

Output: Detailed issues with success criteria, time estimates, test requirements

🔶 AWS: CodeBuild → S3 logging

2

GitHub Auto-Organization

Issues pushed via GitHub API: Automated issue creation with labels

Project workflows trigger: Auto-organize by labels, repos, schemas

Projects populated: Right issues → Right projects → Right priority

Example: Issue with `label:bug` + `repo:execution-services` → "Execution Services" project + "Bugs" project

🔶 AWS: EventBridge → Lambda for automation

3

Agent Deployment (User-Driven)

Local testing: Multi-repo UI → Cursor CLI (developer machine)

UI: Currently on Cloud Run (migrating to AWS)

User selects: Issue list + Model (Claude via Bedrock, GPT, etc.)

Parallel deployment: 5-50 concurrent agents

Cloud scaling: ECS Fargate or Lambda for auto-scaling to 100+ agents

🔶 AWS: ECS Fargate or Lambda, EC2 for VMs

4a

Success Path: Auto-Merge

Quality gates (4 phases):

  1. Local auto-fix (ruff format, ruff check --fix)
  2. Local verify (--no-fix, tests, imports) → EXIT if fail
  3. Pre-commit hooks (same checks again)
  4. CI/CD (GitHub Actions + CodeBuild) → Block auto-merge if fail

PR created: Via quickmerge.sh with "Fixes #XXX"

Auto-close: GitHub workflow closes issue on merge

🔶 AWS: CodeBuild runs Phase 4, logs to S3

4b

Failure Path: Bug Creation & Linking

Quality gates fail: After 3 attempts, create diagnostic

Failure logged: S3 bucket + CloudWatch Logs

Bug issue created: Detailed failure analysis, stack traces, attempted fixes

Cross-reference: Bug blocks original issue (GitHub issue linking)

When bug is fixed: PR with "Fixes #BUG #ORIGINAL" closes both issues

🔴 AWS: S3 for logs, Athena for failure analytics

5

Retry or Human Intervention

Automatic retry (CODs, small tasks):

  • Retry with same model (1-2 times)
  • Escalate to better model if failures persist (Claude 3.5 → Opus)
  • Fully autonomous for 80% of failures

Human escalation (complex tasks):

  • Manual review of failure logs
  • Reassign to different agent or human developer
  • Update success criteria if needed

🔶 AWS: Bedrock for failure analysis, Lambda for retry logic
