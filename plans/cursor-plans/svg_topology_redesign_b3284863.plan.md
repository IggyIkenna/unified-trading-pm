# Runtime Topology SVG Redesign

## Problem

The current SVG (generated by [generate_topology_svg.py](unified-trading-deployment-v3/configs/generate_topology_svg.py)) is missing:

- **Deployment targets** per service (VM / Cloud Run Service / Cloud Run Job)
- **Protocol details** on edges (WebSocket, PubSub, HTTP/SSE, in_memory)
- **Domain data names** on edges (what's flowing)
- **PubSub topic templates** per service
- **Persistence/transport badges** per node (replaces 25+ weak dotted lines)
- **Reference panels** (recovery, circuit breakers, error retry, bootstrap)
- **API auth** (OAuth) and **UI deployment model** (Cloud Run Service)

The SSOT also lacks an explicit per-service deployment target table.

---

## Phase 1: SSOT Updates

### 1a. Add deployment targets to RUNTIME_TOPOLOGY_DECISIONS.md

New **Section 21: Deployment Targets** table:

- **VM (co-located group)**: market-tick-data-service, market-data-processing-service, execution-service — continuous WebSocket/in_memory, co-located on same VM
- **VM (standalone)**: ml-training-service — heavy compute, ~2hr training runs
- **Cloud Run Service (always-on)**: strategy-service, position-balance-monitor-service, risk-and-exposure-service, alerting-service, ml-inference-service (live mode)
- **Cloud Run Service (auto-scale)**: execution-results-api, market-data-api, deployment-api, all UIs
- **Cloud Run Job (scale-to-zero)**: instruments-service, features-calendar-service, features-onchain-service, pnl-attribution-service, strategy-validation-service, client-reporting-api
- **Cloud Run Service (features-live)**: features-delta-one-service, features-volatility-service, features-cross-instrument-service — batch=scale-to-zero, live=always-on

Include a "UI Deployment" note: All UIs are Cloud Run Services serving the React/TypeScript static build. UI and API are deployed as **separate** Cloud Run Services (separate repos, separate scaling). All API endpoints use **OAuth** authentication.

### 1b. Add deployment_targets to runtime-topology.yaml

Add a new `deployment_targets` section mapping each service to its deploy type (`cloud_run_job`, `cloud_run_service`, `vm`, `vm_colocated`), scaling mode, and reason.

Update `deployment_modes.scale_to_zero` to remove `ml-training-service` (move to new dedicated section noting VM).

## Phase 2: Redesign generate_topology_svg.py

### 2a. Enriched node labels (4 lines per node)

Each service node shows:

- **Line 1**: Service name + **deployment badge** (`VM`, `CR Svc`, `CR Job`)
- **Line 2**: Trigger type (e.g., `~15s candle timer`, `event-driven`, `~quarterly batch`)
- **Line 3**: Sharding dims abbreviated (e.g., `B: cat x venue x date`)
- **Line 4**: **Sinks badge** (`-> GCS + PubSub` or `-> GCS only`)

API nodes add: port, `OAuth`, protocol (`HTTP REST + SSE`), data sources.
UI nodes add: `Cloud Run Service`, which API(s) they consume.

### 2b. Remove ALL dotted persistence sink edges

The current script draws 15 edges to GCS and 10 edges to PubSub as weak dotted lines. **Delete all of them.** Replace with the "Sinks: GCS + PubSub" badge on each node (Phase 2a, line 4).

Keep only explicit Redis edges (execution-service hot state, MDPS candle cache) since Redis is exceptional.

### 2c. Enriched edge labels with domain data + protocol

Each pipeline edge shows:

- **Domain data name** (e.g., `raw_tick_data`, `processed_candles_ohlcv`, `delta_one_features`)
- **Protocol shorthand**: `B:GCS | L:PS` or `B:GCS | L:PS | CoLoc:mem`

Source: [RUNTIME_TOPOLOGY_DECISIONS.md Section 7](unified-trading-deployment-v3/configs/RUNTIME_TOPOLOGY_DECISIONS.md) (data lineage table) and [runtime-topology.yaml service_flows](unified-trading-deployment-v3/configs/runtime-topology.yaml).

### 2e. Reference panels (Graphviz record nodes)

Add 4-5 "record" shaped nodes positioned below or to the right of the main DAG using `rank=sink` or invisible edges:

- **Legend**: Edge color/style meanings
- **Recovery Chains**: CeFi (WS -> REST -> Tardis -> GCS), TradFi (WS -> Databento -> IBKR -> GCS), DeFi (RPC reconnect -> block replay)
- **Circuit Breakers**: risk-breach -> alerting -> HALT exec+strategy; manual kill switch via deployment-api
- **Publish + Persist**: "publish PubSub + persist GCS in PARALLEL, consumer deduplicates by timestamp"
- **Deployment Modes Summary**: always-on (7 svc), scale-to-zero (7 svc), auto-scale (3 API), features-live (3 svc)

Source: [RUNTIME_TOPOLOGY_DECISIONS.md Sections 13-17](unified-trading-deployment-v3/configs/RUNTIME_TOPOLOGY_DECISIONS.md).

### 2f. PubSub topic template in node tooltips

Use SVG `<title>` elements (Graphviz `tooltip` attr) to add detailed info per node:

- Full PubSub topic template (e.g., `raw-ticks-{venue}-{inst_type}-{data_type}`)
- Full batch + live sharding dimensions
- Recovery method

This keeps the node label clean while making detail accessible on hover.
