# L0 doc-index generator (grep-native map) + FF-cron auto-regen

> **W4** of `agent_operating_framework_master` — the CONSUMER of the frontmatter (the actual retrieval payoff). Built
> NOW so it is ready as docs migrate to the new frontmatter (operator 2026-06-24). The L1 facets (frontmatter) are the
> input; this L0 map is what agents read FIRST to route — "retrieve less but right".

## Shipped

- **`scripts/docs/gen_doc_index.py`** — walks the doc corpus (plans/epics/issues/audit/codex + the cross-repo
  `agent-orchestrator/agents`), parses frontmatter (reuses `docspec`), and emits an `llms.txt`-style **L0 map**: one
  greppable line per doc —
  `- [title](repo-root-rel-path) — summary  ·  [doc_type=… asset_group=… stage=… repos=… status=… …]` — grouped by
  `doc_type`, deterministically sorted. **1,124 docs** indexed today; un-migrated docs show `(no summary yet)` +
  whatever facets exist (fills in as the rollout proceeds). **Resilient**: a doc with malformed YAML frontmatter is
  skipped, never crashes the index.
- **Output is CONSUMER-SIDE LOCAL + gitignored** (`/DOC_INDEX.generated.md`, C2) — deterministic (sorted, no timestamps,
  repo-root-relative → byte-identical across hosts), so every host regenerates its own copy with **zero git contention**
  (no committed fleet-shared index = no multi-writer hotspot).
- **FF-cron auto-regen — written, landing PENDING.** The regen call (guarded, `timeout 60`-bounded, `|| true`,
  `--stale-check`) is authored for the end of `scripts/dev/slot-cron-ff-pull.sh`. But it can't be edited in place on the
  MAIN clone: the crontab's FF-pull line has a **self-bootstrap** step that `mv`s origin's `slot-cron-ff-pull.sh` over
  the local copy **every 5 min** (so the cron always runs the latest script) — overwriting any local edit, HEAD never
  moves. So the hook must reach origin first: land it via a **slot clone** (the `mv` targets only the main clone), OR
  use a **standalone cron line** (`*/5 … gen_doc_index.py --stale-check`) — operator's pick. Until then, run the
  generator on-demand.
- **`scripts/docs/test_gen_doc_index.py`** — determinism + smoke tests (3, green).

## Grep examples (what the L0 map buys)

```
rg 'asset_group=[^]]*defi'                 DOC_INDEX.generated.md   # all defi docs
rg '^## codex-ssot' -A999999               DOC_INDEX.generated.md | rg 'authoritative_for=.*manifest'
rg 'doc_type=plan .*assigned_vm=vm-defi'   DOC_INDEX.generated.md   # defi plans dispatched to vm-defi
```

## Decisions / lessons (operator 2026-06-24)

- **Content fields (`summary`/`tags`/`status`) are done during the FULL ROLLOUT, not separately** — they are the
  expensive half; folded into the per-doc-type migration.
- **The full rollout (all doc types, ~few-hundred docs) runs in a coordinated SILENT WINDOW** — updating that many docs
  while other agents/crons are active causes constant conflicts (proven on the 5-per-type sample: a peer's live edit
  collided on `sports_manifest`; the FF-cron clobbered an uncommitted `slot-cron-ff-pull.sh` edit). At full scale that
  is unworkable, so the rollout is gated on a quiet window.
- **Editing a file the FF-cron itself pulls (e.g. `slot-cron-ff-pull.sh`) must be committed promptly** — an uncommitted
  edit to it is clobbered on the next cron tick. Landed this one by briefly holding the cron's flock during the ship.

## Success criteria

- A deterministic, gitignored L0 index is generated from frontmatter and auto-refreshed by the FF-pull cron.
- Re-running the generator is byte-identical (proven by test) → no git contention.
- The cron hook can never hang or fail the FF sweep (guarded + timeout + `|| true`).
