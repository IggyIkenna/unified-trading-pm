# Catalogue audit — sports (cross_asset_group plan)

## Methodology

Reconciled, from this `.tabs/8` worktree, the sports SSOT layers that ARE present: UAC capability declarations (`_sports.py`), sports venue constants + classification (`_sports_venue_constants.py`, `venue_constants.py`), market-data axis (`VENUES_BY_ASSET_GROUP["sports"]` / `DATA_TYPES_BY_ASSET_GROUP["sports"]`), coverage windows (`league_data.py` `SOURCE_COVERAGE_START` / `DATA_TYPE_COVERAGE_START` / `KNOWN_COVERAGE_GAPS`, `season_dates.py`), the venue manifest (`betting_sports.py` `BETTING_SPORTS_VENUES`), sports GCS path SSOT (`gcs_paths.py`), instruments-service reference-data adapters (`reference_data/adapters/sports/factory.py` + `reference_data/factory.py` + `router.py`), and MTDS market-data adapters (`market_interface/sports/registry.py` + `market_interface/adapters/sports/` + `engine/orchestrator.py` sports data_types). **URDI caveat**: the bulk of sports *execution* and *reference* adapter code lives in `unified-sports-execution-interface` (`unified_sports_execution_interface.adapters.*`) and the sports-reference interface (sometimes called URDI/USRI) — **neither repo is checked out in this worktree**. The MTDS sports `_ADAPTER_PATHS` registry routes ~20 of its keys (betfair / matchbook / onexbet / odds_api / bet365 / williamhill / ladbrokes / paddypower / betfred / betvictor / boylesports / bwin / betway / unibet / bet888sport / sbo / skybet / coral) to those non-present packages. Findings about that surface are marked `URDI-GAP — not auditable from this worktree`, not "missing". `e2e-testing/scripts/sports/`, `features-sports-service`, `new-sports-batting-services` are also absent here (noted, not deep-dived).

## Coverage summary

Sports SSOT is in decent shape on the parts auditable from this worktree: the empty-confirmed reason taxonomy is consistent and complete (SP-8), the banned live-only-data_type split (`LINEUPS_PRE/POST_MATCH`) is absent (SP-9), the sports-reference GCS path SSOT is the canonical `sports_reference/by_date/...` layout with no legacy `category=` key drift (SP-11), and per-source coverage windows + per-league season windows exist without a double-SSOT for season dates. The real drift is: one capability **GHOST** (`manifold`, SP-1), one capability **omission** (`open_meteo` weather source, SP-2), pervasive **venue-id casing drift** across the sports axis (SP-3 — wider than the cross-asset plan flagged), an **undocumented dual data_type namespace** (`odds` market-data vs `ODDS` reference, SP-4), an **empty `KNOWN_COVERAGE_GAPS`** that contradicts the 2026-05-11 phantom-recon's pre-launch-row clusters (SP-6), and — the biggest gap — **the entire URDI / sports-execution-interface adapter surface is not in this worktree** (SP-5, SP-10, SP-12), so error-classification / `ADAPTER_FETCH_FAILED` / typed-empty-reason / cluster-validation / capability-decl-vs-adapter-method reconciliation for ~20 sportsbook + exchange + aggregator venues is unverified and needs a dedicated audit pass from a worktree that has those repos. **BIG finding flag**: SP-3 (cross-repo SSOT casing drift on a May-23-adjacent axis) and SP-12 (whole adapter layer un-auditable here) are the two that warrant operator attention — neither is a data-correctness bug today, but both would change the catalogue-audit work-split (Phase-1D scope; a new URDI-side audit Tab).
