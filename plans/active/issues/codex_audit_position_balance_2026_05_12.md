# Codex audit — Position-balance area (Phase 1.F)

> **Severity**: P1 — pre-cutover audit per `codex_vs_citadel_infrastructure_audit_2026_05_10.md` Phase 1.F.
> **Scope**: per-client position/audit-record lineage (GCS `audit/{client_id}/{date}/{event_type}/`, append-only, 7yr retention) · batch-vs-live reconciliation (`batch-live-reconciliation-service`, master-plan readiness item F-21) · custody pings (Copper + CEFFU, master-plan item F-19) · position-balance-monitor as the positions SSOT · `batch=live` symmetry for position tracking.
> **Owner**: Harsh T8 slot 8 sub-agent (Day-4 stretch); operator review for dispositions before Phase 3 ship.

## Methodology

Read every Position-balance / reconciliation / custody / audit-record surface in `codex/04-architecture/`, `codex/05-infrastructure/`, `codex/07-security/`, `codex/15-runbooks/alerting/` (anchor list of ~8 docs + cross-referenced sweeps). For each rule / pattern / claim: cite file:line, classify KEEP / LIFT / CONSOLIDATE / DELETE / ADD, attach a 1-line reason + suggested disposition (IMMEDIATE / PRE_CUTOVER / POST_CUTOVER) + owner. Cross-checked against `execution-service` audit-log writer, `strategy-service` signal-publisher audit emission, `position-balance-monitor-service` core/v2 reconciliation engines, `batch-live-reconciliation-service` stage DAG, and the UAC `internal/schemas/audit.py` + `internal/reconciliation.py` machine-readable SSOTs. Several findings come from grep-then-READ (e.g. the `audit/{client_id}/...` path template literally appears in codex AND in code, but the *actual written path* diverges).
