# Workspace QG baseline sweep — 2026-05-11

> **Severity**: P1 — gates `code_freeze_migrate_backfill_sequencing_2026_05_10.md` Phase 1 freeze gate item 8
> (2026-05-15 hard freeze). **Blast radius**: 22 active Python repos. **Suggested owner**: slot 6 (this is its running

> logical unit per CLAUDE.md "QG failure attribution".

## Constraint — full QG can't run in a slot worktree without `setup.sh` first

The per-slot worktrees at `${WORKSPACE_ROOT}/.tabs/<N>/` are created by `setup-tab-worktrees.sh --init` via
`git worktree add` only (~1s/repo) — they do **not** get per-repo `.venv`s. `bash scripts/quality-gates.sh` (which runs
basedpyright + pytest + the 60+ STEP checks) needs the repo's `.venv` with all deps installed. So a full workspace QG
sweep from slot 6 requires running `bash scripts/setup.sh` in each slot repo first (~1-3 min/repo, ~30-60 min for all 22
— affordable over the 4-day cycle but not free). **Plan**: day 1 = static baseline below (ruff + `# type: ignore`,
neither needs a venv); days 2-4 = `setup.sh` + full `quality-gates.sh` on the repos slots 2-5 actually touch, plus a
broader sweep mid-cycle. The full-QG-green check for freeze-gate item 8 will be done on/before 2026-05-14. (The
day-to-day enforcement of QG green is each slot running `bash scripts/quality-gates.sh` before its own pushes per
CLAUDE.md "Commit + Push + Flip" — slot 6 is the cross-cutting validator + regression-attributer, not the only gate.)

**Additional slot-worktree caveat (observed 2026-05-11 PM):** even when a `python3 -m pytest <test>` _can_ be invoked
from a slot worktree (pyenv's interpreter has `pytest`+`pyyaml`), the editable installs in the venv that gets used
(`.venv-workspace` or pyenv site-packages) **cross-reference other slots' worktrees** — e.g. running
`unified-trading-library` tests from `.tabs/6/unified-trading-library/` imported `unified_api_contracts` from
`.tabs/2/unified-api-contracts/` (slot 2's worktree on `tab/ikennaigboaka/2`), which is at a different branch state →
`ImportError: cannot import name 'BAR_TIMEFRAME_SECONDS'`. So pytest results from a slot worktree are **not
trustworthy** even when they run. Composes with the MTDS-slot-worktree-QG quirk (`bash scripts/quality-gates.sh` for a
service runs _PM's_ tests when PM is a sibling worktree — folded into `per_agent_worktrees_2026_05_10.md` Phase 4.5 per
operator decision 2026-05-11). Net: a slot worktree is a reliable place for `ruff`/AST/yaml static checks + reading
code; it is NOT a reliable place for pytest/basedpyright until the per-slot venv + editable-install resolution is fixed
(Phase 4.5). The days-2-4 full-QG-green check must run from a properly-`setup.sh`'d environment (or a fresh clone), not
a slot worktree.
