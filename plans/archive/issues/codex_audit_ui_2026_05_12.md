# Codex audit — UI area (Phase 1.K)

> **Severity**: P1 — pre-cutover audit per `codex_vs_citadel_infrastructure_audit_2026_05_10.md` Phase 1.K. **Scope**:
> tier-based startup (`dev-tiers.sh --tier static|0|1|2`, legacy PM-based `dev-start.sh`) · mock vs real (5 axes +
> `runtime_profile` v7 collapse + presets `ci|mock|api-real|real`) · firebase-local emulator suite · deployment-ui
> surfaces (port 5183, 6 lifecycle tabs incl. Data Status, `restart-deployment-stack.sh`) · the "13 UIs" inventory ·
> port registry (`ui-api-mapping.json`) · Vitest `pool: "forks"` · TS strict mode · UI-is-own-repo. **Owner**: Harsh T8
> slot 8 sub-agent (Day-4); operator review for dispositions before Phase 3 ship.

## Methodology

Read every UI-related codex doc in full (8 anchor docs + cross-referenced sweeps), and cross-checked each rule / claim
against actual workspace state: `unified-trading-pm/scripts/dev/ui-api-mapping.json` (port SSOT),
`unified-trading-system-ui/scripts/dev-tiers.sh` (tier-startup SSOT), `vitest.config.ts`, `next.config.mjs`,
`restart-deployment-stack.sh`, and `workspace-manifest.json` `repositories` (the active-repo SSOT). For each finding:
file:line evidence, classification KEEP / LIFT / CONSOLIDATE / DELETE / ADD, 1-line reason, suggested disposition
(IMMEDIATE / PRE_CUTOVER / POST_CUTOVER), suggested owner. Several findings come from grep-then-READ — e.g. the literal
"13 UIs" string is still in CLAUDE.md + multiple archived plans, but `workspace-manifest.json` lists only 3 UI repos
(`unified-trading-system-ui` / `deployment-ui` / `user-management-ui`) and the workspace clone has only 2.
