## Methodology

Reconciled, from this `.tabs/8` worktree, the sports SSOT layers that ARE present: UAC capability declarations
(`_sports.py`), sports venue constants + classification (`_sports_venue_constants.py`, `venue_constants.py`),
market-data axis (`VENUES_BY_ASSET_GROUP["sports"]` / `DATA_TYPES_BY_ASSET_GROUP["sports"]`), coverage windows
(`league_data.py` `SOURCE_COVERAGE_START` / `DATA_TYPE_COVERAGE_START` / `KNOWN_COVERAGE_GAPS`, `season_dates.py`), the
venue manifest (`betting_sports.py` `BETTING_SPORTS_VENUES`), sports GCS path SSOT (`gcs_paths.py`), instruments-service
reference-data adapters (`reference_data/adapters/sports/factory.py` + `reference_data/factory.py` + `router.py`), and
MTDS market-data adapters (`market_interface/sports/registry.py` + `market_interface/adapters/sports/` +
`engine/orchestrator.py` sports data*types). **URDI caveat**: the bulk of sports \_execution* and _reference_ adapter
code lives in `unified-sports-execution-interface` (`unified_sports_execution_interface.adapters.*`) and the
sports-reference interface (sometimes called URDI/USRI) — **neither repo is checked out in this worktree**. The MTDS
sports `_ADAPTER_PATHS` registry routes ~20 of its keys (betfair / matchbook / onexbet / odds_api / bet365 / williamhill
/ ladbrokes / paddypower / betfred / betvictor / boylesports / bwin / betway / unibet / bet888sport / sbo / skybet /
coral) to those non-present packages. Findings about that surface are marked
`URDI-GAP — not auditable from this worktree`, not "missing". `e2e-testing/scripts/sports/`, `features-sports-service`,
`new-sports-batting-services` are also absent here (noted, not deep-dived).
