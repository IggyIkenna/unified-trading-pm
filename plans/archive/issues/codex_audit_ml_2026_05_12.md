# Codex audit — ML area (Phase 1.E)

> **Severity**: P1 — pre-cutover audit per `codex_vs_citadel_infrastructure_audit_2026_05_10.md` Phase 1.E. **Scope**:
> ML lifecycle (train → register → promote → infer) · training/inference colocation claim · cache-delta / Pub/Sub
> model-artefact hot-reload · lookahead-bias `available_at` discipline as applied to ML training · `pickle` ban
> (joblib/JSON/Parquet/ONNX only) · ML feature orchestration & registry in UTL · ml_training / ml_inference
> service-infra requirements (`ServiceBootstrap`, `make_health_router`, typed config reloaders) · ML model-artefact
> bucket-naming SSOT. **Owner**: Harsh T8 slot 8 sub-agent (Day-4 stretch); operator review for dispositions before
> Phase 3 ship.

## Methodology

Read every ML-area codex surface (anchor list of ~12 docs spanning `04-architecture/`, `16-strategy-playbooks/ml/`,
`15-runbooks/alerting/`, `02-data/`, `09-strategy/`, `14-customer-journeys/`, `06-coding-standards/`). For each rule /
pattern / claim: cite file:line, classify KEEP / LIFT / CONSOLIDATE / DELETE / ADD, attach a 1-line reason + suggested
disposition (IMMEDIATE / PRE_CUTOVER / POST_CUTOVER). Cross-checked against code in `ml-training-service/`,
`ml-inference-service/`, and `unified-trading-library/unified_trading_library/ml/` — most findings come from
grep-then-READ (read `model_loader.py`, `model_promotion_subscriber.py`, `drift_monitor.py`, UTL `model_registry.py`,
`config_reloaders.py`), not literal-grep-only conclusions. `unified-features-interface` is NOT checked out in this
worktree — feature-orchestration cross-checks limited to UTL `ml/` + the codex `features-service-architecture.md`.
