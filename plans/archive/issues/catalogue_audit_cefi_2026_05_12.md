## Coverage summary

The cefi catalogue is internally inconsistent in three structural ways: (1) **venue-id casing/granularity is not
uniform** across the SSOTs — `VENUES_BY_ASSET_GROUP` uses uppercase spot/futures-split ids while `coverage_starts.py`,
`data_type_capability.py` (partly), `_cefi.py`, `cefi_margin_tiers.py`, and `_BASE_VENUES_BY_ASSET_GROUP` use bare
lowercase or differently-suffixed ids, so cross-SSOT joins (honest-coverage clip, data_type pre-flight,
instruments-service adapter dispatch) silently miss venues; (2) **GMX and DRIFT are still double-booked** as both cefi
venues (bare) and defi protocols (suffixed) — DRIFT-as-cefi is a pure ghost (no MTDS / no exec / no instruments path),
GMX-as-cefi has only a funding-subgraph path; (3) **writegate Wave 3.M (zero-activity bars) has not started** — no cefi
venue emits Category-D bars, so the volatility-smile / cross-instrument-completeness use case is unmet for every cefi
data_type. **BIG findings (operator notify): CF-1/CF-2/CF-9/CF-10 (GMX+DRIFT dual-classification/ghosts — cross- repo
SSOT contradiction on a May-23 critical path), CF-15 (Wave 3.M zero progress — data-correctness gap for all 21 cefi
venues), CF-4/CF-7/CF-8 (coverage-window + data_type-capability key-mismatch — affects honest-coverage % accuracy for ≥8
cefi venues).** None of these are new code regressions; all are pre-existing SSOT drift the plan already owns (Phases
1C/1D/3) plus writegate Wave 3.M.
