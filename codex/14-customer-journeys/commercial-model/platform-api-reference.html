01

Authentication

partial✓ verified owner: code_readiness_t1_contracts_library_externalapi

All three services gate their counterparty routers with the same shared dependency — unified_trading_library.cloud_interface.api_auth.create_api_auth(api_name). One mechanism, one set of header names, one precedence order, everywhere.

Header precedence, and what each path returns

The dependency checks, in this exact order, the first one present wins (unified-trading-library/unified_trading_library/cloud_interface/api_auth.py:319-387):

Order Header Resolves to Failure
1 DISABLE_AUTH / mock mode Auto admin context — local dev only, hard-blocked in staging/production by _check_production_safety —
2 X-Service-Token Internal/admin AuthContext (S2S) if it matches the configured service token 403 Invalid X-Service-Token
3 X-API-Key (legacy) Admin AuthContext, is_api_key=true, if it matches UnifiedCloudConfig().api_key 401 Invalid API key
4 Authorization: Bearer <jwt> HS256 JWT — claims below become the AuthContext 401 Token expired — please log in again or Invalid token: …
5 None of the above — 401 Not authenticated. POST /auth/login to get a token, then send Authorization: Bearer <token>.
JWT claims (HS256) — api_auth.py:16-25
{ "sub": "user-id", "org_id": "org-123", "role": "admin" | "internal" | "external", "subscription_tier": "enterprise" | "data-pro" | "data-basic" | "free", "exp": <unix timestamp>, "iat": <unix timestamp> }
AuthContext — the object every route sees after auth passes (api_auth.py:109-125)
class AuthContext: org_id: str user_id: str # "sub" claim role: str # admin | internal | external subscription_tier: str display_name: str is_internal: bool # true for admin or S2S is_api_key: bool
What auth does not do on these three routers, stated exactly

✓ verified On instruments-service, the endpoint itself discards AuthContext after the dependency runs (del auth, instruments-service/instruments_service/api/routers/external.py:86) — every authenticated caller sees the same catalogue, because this is public reference data, not a per-client ledger. On market-tick-data-service the auth dependency is mounted at the router level (dependencies=[Depends(_api_auth)], market-tick-data-service/market_tick_data_service/api/routers/external.py:52-56) and no endpoint function receives an AuthContext argument at all — auth is a gate, not a scope. On execution-service, auth.org_id is written to the audit log alongside the instruction (execution_service/api/external_instruction_api.py:144) but is not checked against the instruction's own identity.client_id — the caller-supplied client_id is not validated against the authenticated org in this router.

Whether each individual service also mounts the shared /auth/login / /auth/me router (create_auth_router, same file) is not verified on this page — ? check. Token issuance/provisioning is an operator-side integration step, out of scope for this reference.

Instructions API — execution-service

partial✓ verified owner: execution_master

One instruction envelope, any asset class — but only one of its fifteen action types actually executes today. execution-service/execution_service/api/external_instruction_api.py.

Read this before anything else on this page

Only TRADE is wired end-to-end. The request body type, StrategyInstructionV2, is a 15-member discriminated union (unified-api-contracts/unified_api_contracts/internal/architecture_v2/schemas.py:299-489). A TRADE instruction is translated and routed through the same ManualOperationHandler.execute() → LiveOrchestrator.execute_instruction() path the internal DART manual-trade surface uses in production. The other fourteen variants — SWAP, LEND, BORROW, WITHDRAW, REPAY, STAKE, UNSTAKE, QUOTE, TRANSFER, BRIDGE, ATOMIC, CANCEL, LP_MINT, LP_BURN — parse successfully (they are real, valid members of the union) but return an honest 501: not a silent drop, but not the same contract either (external_instruction_api.py:129-136).

05

Strategy-service — no counterparty surface

planned✓ verified owner: execution_master

Stated plainly rather than left implicit: strategy-service exposes no counterparty-facing API today.

Its real endpoints are admin-token-gated internal tooling — registry reads, a restriction-profile router, an operational-mode flip — built for our own operators, not for an external caller. There is no path from this service to an outside caller comparable to the three routers documented above. If and when one is built, it will appear on this page with real parameters and real examples, not before.

Error reference

Every status code used anywhere on this page, consolidated.

Status Meaning Seen on
400 Malformed parameter, or a business-rule violation (bad asset_group, mismatched file, missing target_venue, unresolvable direction) Instruments GET/bulk, instructions POST, market-data batch delivery
401 Not authenticated — no valid token/key on the request All six endpoints
403 X-Service-Token present but wrong All six endpoints
404 Nothing matches — no shard, no object, no coverage measurement in the lookback window Instruments bulk, market-data availability & batch delivery
422 Request validation failed — bad enum value, or a body that matches none of the 15 instruction variants Market-data (asset_group / topology / after), instructions POST
500 Unhandled server-side error All six endpoints
501 Recognised but not wired for external submission — 14 of the 15 StrategyInstructionV2 variants Instructions POST
503 Unavailable — kill switch armed, service draining, config missing, or bucket resolution failed Instructions POST, market-data availability & batch delivery
