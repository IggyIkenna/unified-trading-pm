# Roadmap — what comes after this SSOT

The playbook SSOT is the CANONICAL IA. Actually implementing everything it describes is a multi-plan journey. This
directory tracks the follow-up plans so the end-to-end picture is never lost.

> User quote: "I don't want to lose sight of the whole picture end to end. Even if it has to be broken down into three
> plans, I want to have the first plan understanding that there's more to go and the details of where to find that
> information we have about that so far."

## Sibling docs

- [next-waves.md](next-waves.md) — the 8 known follow-up work items, each with owner + existing-plan reference +
  new-plan-needed flag
- [plan-references.md](plan-references.md) — for each follow-up wave, where the current information lives (memory
  entries, existing plans, needs-new-plan)

## How to use

When you read a playbook doc and see a mention of a gap, a "needs implementation", or an orphan awaiting triage decision
— check [next-waves.md](next-waves.md). Every identified gap is tracked there with its current state.

When starting a new plan that touches any of the concerns in this SSOT — check [plan-references.md](plan-references.md)
to avoid duplicating work already planned.
