# 13 — Codex Governance

Meta-governance for the unified-trading-codex itself: the rules for what goes where, why, and how to keep the codex and
the PM repo cleanly separated.

## Contents

| File                  | Purpose                                                        |
| --------------------- | -------------------------------------------------------------- |
| `SSOT-BOUNDARY.md`    | The canonical decision tree for codex vs PM content placement  |
| `SECTION-REGISTRY.md` | All 14 codex sections: name, purpose, update trigger, examples |

## Why this section exists

The codex and `unified-trading-pm` have complementary but distinct roles. Without an explicit written rule, content
drifts into the wrong repo — stale roadmaps accumulate in codex, architectural standards fragment across PM plans, and
agents don't know where to look.

This section makes the boundary rules first-class, findable content.

## Quick rule

**Codex answers "what must be true." PM answers "what is happening right now."**

See `SSOT-BOUNDARY.md` for the full decision tree.
